# 终端实时区与历史区的连续滚动

日期：2026-09-18
项目：`/Users/kaifengwang/Documents/myDev/DuoCLI`

## 本次反馈

用户在最新位置用鼠标向上滚动时，画面突然变为黑色，出现“回到最新”胶囊；反向滚动不能自然回到最新，内容位置和滚动方式也有明显切换感。

## 确认的原因

网页历史层背景写死为 `#0d1117`，没有使用当前终端主题；桌面历史状态还会隐藏原 xterm。历史请求发出后立即展示空的历史层，第一批数据到达时又把位置改到历史页尾。这是两套视图之间的硬切换，而不只是滚动速度问题。

原历史层只处理向上翻页，缺少把反向滚轮交还实时终端的路径。胶囊因此成了必需操作。原来的测试主要分别检查跟尾、分页、复制，没有验证两种视图之间的一整次来回过程。

## 交互修改

1. 历史层保留当前 xterm 的可视画面作为衔接尾段，包括 DOM 或 canvas 的可视内容，不重新解析一屏 ANSI。它只是不可交互的视觉预览，不启动第二个终端。
2. 背景、字体、字号、行距和文字网格宽度取自当前终端；加载提示悬浮，不再挤动阅读区域，也不会先盖上一整块空黑背景。
3. 新历史从当前画面的上方接入，初始位移来自滚轮实际距离，不再整屏切换到另一段内容。
4. 识别历史页与本地有限滚动缓存的重叠部分，避免接缝重复。最多补取四页完成对齐；边界无法识别时保留收到的内容，不猜测删除未知输出。
5. 向下滚动到衔接尾段后，恢复原来的本地位置并传递剩余滚动距离；本地尚有缓存时继续向下浏览，不越过它直接跳到最新。到达最新后恢复跟随。
6. 胶囊仅是可选快捷操作。小幅回滚且无新输出时不显示；明显离开底部或出现未读输出时才显示。
7. 等待请求期间反向滚动也能取消历史过渡，迟到数据不会把已经返回的用户再次带进历史。
8. 保留阅读时不被新输出拉走的行为；重连后的实时预览可刷新，而归档阅读行和像素偏移不变。
9. 桌面一屏终端等待较慢历史元数据时，不再把“尚无本地位移”误判成用户要求恢复跟尾。

## 修改范围

- `mobile/client/terminal-history-layer.js`：连续衔接、主题与网格对齐、缓存重叠识别、滚轮/触摸返回、预览刷新。
- `mobile/client/app.js`：网页滚轮距离传递、实时区恢复、重连预览刷新。
- `src/renderer/terminal-manager.ts`：桌面实际入口及本地缓存交接。
- `src/renderer/terminal-scroll-controller.ts`：方向意图及剩余位移，不让旧跟尾回调取消上滚。
- 两端 CSS：取消强制隐藏实时画面，提示不占据布局高度。
- `mobile/client/sw.js`：资源缓存更新为 `duocli-v73`。
- `package.json`：新测试加入 `test:terminal` 与 `test:e2e`。
