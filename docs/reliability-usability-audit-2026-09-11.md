# DuoCLI 可靠性与手机易用性体检

日期：2026-09-11。范围：当前工作区（包含原有未提交修改），桌面 Electron、手机 PWA、远程服务、终端输入与恢复。本文件保留初始体检证据；列出的高优先级问题已在本轮工作区修复，最终验证结果以实际测试命令为准。

## 总体判断

核心终端链路已有较好的保护，但还不能把“正常网络下能用”理解为“日常跨设备使用可靠”。主要短板集中在会话切换、网络切换、输入草稿、文件上传和长期运行。建议先修复内容归属与恢复问题，再优化手机操作密度。

已具备的基础：提交 ID 去重、WebSocket 与 HTTP 提交共用去重、回放与输出顺序保护、历史滚动保护、中文输入法处理、关闭会话恢复确认、远程健康检查、Android 控制确认与租约、桌面关窗保留远程服务。应继续保留这些机制。

## 验证范围与结果

- `npm run build:ts`：通过。
- `npm run test:unit`：142/142 通过。
- `npm run test:e2e`：完整脚本通过，共 72 项检查（手机 40、桌面复制 4、桌面滚动 10、真实远程服务 18）。
- 额外隔离浏览器探针：使用当前手机页面、现有 E2E 模拟后端、390×760 触摸视口；复现草稿串会话、刷新丢稿、上传串会话、跨源返回地址丢失，并模拟验证响应体卡住时超时保护失效。
- 运行环境是 Node 26.7.0，与仓库要求的 Node 20 不同；本次结果不替代 Node 20 CI 验证。
- 未操作用户正在运行的终端，未做真机 Safari/PWA、蜂窝弱网、真实锁屏/休眠、长时间压力测试。下述“静态确认”与“待实测风险”不等同于真机复现。

## 优先修复：影响正确性与可靠性

### 1. 草稿串会话与刷新丢失｜P1，浏览器复现

场景：在 A 输入未发送内容，返回列表进入 B，B 输入框仍显示 A 的内容；刷新页面，内容消失且回到主页。容易把命令发送到错误项目，也让手机长文本输入缺乏保障。

证据：`mobile/client/app.js:3728` 的 `openSession` 不切换草稿；`:3989` 发送读取共享输入框。探针在 B 读取到 `Only intended for session A`，刷新后为空。

改进：以服务端身份与 sessionId 为键保存草稿，切会话先存后取；保存未确认提交的 ID、文本与目标会话。发送过程中继续编辑或切到别的会话，也要保留原提交。失败、已接收、结果未知分别显示；结果未知时沿用原 ID 查询/重试，避免换 ID 重发。刷新可提供“继续上次会话”，但不自动执行旧草稿。

验收：A/B 来回切换、刷新、失败回调晚到、新文本已输入等情况下，各会话内容互不影响；同一未确认提交只执行一次。

### 2. 上传中切会话会改变后续文件目标｜P1，浏览器复现

场景：在 A 选择两个文件，第一个上传未结束时切到 B。探针记录请求依次进入 `/api/sessions/s1/upload` 和 `/api/sessions/s2/upload`，B 输入框同时出现 A、B 两个路径。

证据：`mobile/client/app.js:4207` 附近上传处理逐次读取全局 `currentSessionId`，完成后直接写共享输入框。

改进：选择文件时固定目标会话；上传结果进入该会话的附件草稿。显示目标、进度、取消与逐项重试；统一处理超时、401 和错误响应；路径插入按使用场景处理空格与引号。并发上传时也不覆盖用户新输入。

验收：多文件上传过程中切换、关闭原会话、失败、重试，均不会把文件或路径落到另一会话。

### 3. 公网→局域网后缺失返回地址｜P1，跨源机制复现

证据：`mobile/client/app.js:1145` 把公网 origin 写入当前 origin 的 localStorage，然后导航到另一 origin；`:1153` 在新 origin 读取同名键。localStorage 不跨 origin 共享，代码也没有传递返回地址。用 localhost→127.0.0.1 的隔离导航复现，新页面 `duocli_cloud_url` 为 null。公网 HTTPS→局域网 HTTP 具有相同的存储边界，但本次未实测真实公网链路。

影响：用户离开 Wi-Fi 后，局域网失联自动回公网的逻辑可能直接返回，无法完成恢复。

改进：通过已认证的服务端连接配置，或一次性交接票据传递受校验的公网入口和当前会话；在跳转前准备必要的恢复信息，目标页面确认接收后再报告“已切换”。草稿不能仅假定保存在另一个 origin 的本地存储中。

验收：全新浏览器公网登录→切 LAN→关闭 Wi-Fi→返回公网；仍进入原会话，草稿保留。另测 IP 改变、旧公网地址失效、Token 轮换。

### 4. 网络恢复的超时边界不完整｜P1，模拟复现与静态确认

- `mobile/client/app.js:278`：`api()` 收到响应头就清除超时，然后等待 `r.json()`。模拟响应体不完成时，设 40ms 超时，120ms 后仍 pending，signal 未中止。
- `:3588` 附近：WebSocket 连接超时只关闭 OPEN 连接；仍在 CONNECTING 时只显示提示，未主动结束这次尝试。
- `:4800`：回到前台重置最后心跳时间，没有立即验证仍为 OPEN 的连接是否可通；普通模式失活阈值为 45 秒，弱网模式为 90 秒，存在等待窗口，真机影响待测。
- `:2685`：SSE 错误恢复中的鉴权 fetch 没有超时，且重连触发只覆盖主页/横屏侧栏。详情页出错后可能失去状态更新。
- `:4916` 与 `:4941` 有两条自动登录/进入主页路径，增加重复初始化与竞态风险。

改进：统一请求超时覆盖响应体；支持取消；以连接实例/代次隔离旧回调；CONNECTING 超时结束该连接并重试。前台恢复先发短探活，再恢复可发送状态，避免每次无条件重建终端。登录与 SSE/WS 生命周期统一管理。

验收：响应头到达后断流、握手不返回、连接半开、前后台切换、Token 轮换均有确定结果和重试入口；正常回前台不闪屏、不重复回放、不丢历史阅读位置。

### 5. 长期运行的上下文内存无界增长｜P1，静态确认

证据：`src/main/index.ts:487` 对每次输出执行 `existing + data`，未限制 `sessionContextBuffer` 容量。`:615` 只在桌面关闭并提取历史的路径删除；自然退出回调没有相应清理。不能因为终端 rawBuffer 有限，就认为所有缓存都有限。

改进：上下文使用有界分块缓冲或增量写盘，集中处理所有退出路径的归档与释放，避免大字符串反复拼接。记录缓存字节数与进程内存。

验收：多会话连续大量输出、自然退出、手机关闭、桌面关闭后缓存均受限且释放；做数小时耐久测试观察内存是否持续增长。本次未复现实际 OOM。

## 桌面与手机接力的设计风险

1. **查看手机终端会改变共享终端尺寸。** `src/main/remote-server.ts:573` 附近订阅与首次 resize 会接管尺寸；`src/main/pty-manager.ts:637` 已有尺寸所有者保护。建议明确“跟随查看/接管输入”，查看默认尊重当前操作者尺寸，接管时再切换，提示当前控制端。双端交替输入及 TUI 重排必须回归，不能简单取消尺寸保护。
2. **计划执行依赖桌面 renderer。** `src/renderer/app.ts:315` 的计时器和 `src/main/index.ts:1199` 的配置中转表明主进程不是执行权威。关窗当前是隐藏，不会直接销毁 renderer；不能据此声称关窗必然停计划。但渲染进程崩溃、后台调度、重载都是待验证风险。建议计划执行与持久状态迁到主进程，UI 负责展示与设置，保存后返回可核验结果。
3. **恢复 CLI 对话不等于恢复所有运行任务。** 当前主要靠有 resumeId 的会话账本恢复，不能承诺普通 shell 进程、构建任务在应用退出或电脑重启后继续。建议记录工作区清单，区分“可继续对话”“仅恢复目录”“需重新启动”；对关窗、退出、电脑休眠分别明确远程影响。突然断电/进程崩溃后的恢复需要独立测试。
4. **PWA 更新需要版本一致性验证。** `mobile/client/sw.js` 对 HTML/JS/CSS 分别网络优先，更新时可能混合新旧资源；弱网静态请求也没有明确回退时限。建议资源带版本、提供更新就绪提示，先持久化草稿，再执行更新；测试旧 SW 升级与离线启动。这是设计风险，本次未复现混版故障。

## 建议实施顺序

**第一批：防错与保全。** 会话草稿、未确认提交、上传归属、LAN/公网交接、完整超时与重连、上下文缓存上限。每个问题增加对应行为回归，不以“原测试仍然通过”作为唯一验收。

**第二批：手机高频操作。** 放大触摸区域、明确换行、连续发送保持键盘、底部会话选择器、通知直达、连接状态。保留终端原生工作流，不急着整体重做聊天界面。

**第三批：长期运行与跨设备接力。** 主进程计划调度、工作区恢复、查看/接管模式、版本化更新、诊断导出。导出包含版本、连接状态、最近错误和恢复耗时，排除 Token 与命令正文等敏感内容。

## 发布前应覆盖的真实使用路线

- 电脑开始任务→手机打开→锁屏几分钟→解锁继续输入。
- 公网进入→切局域网→离开 Wi-Fi→蜂窝公网恢复。
- A 输入长草稿→看 B→上传文件→返回 A；所有输入和附件属于正确会话。
- 请求已到电脑但确认丢失→重连→重试，同一命令执行一次。
- 正在读历史时持续输出，键盘弹出/收起、横竖屏切换后不强制跳底。
- 点击“需要确认”通知→正确会话→明确确认/停止操作。
- 电脑关窗与应用退出分别验证；计划执行、远程服务状态与界面提示一致。
- 数小时多会话运行后内存受控；模拟进程重启，恢复范围与提示一致。

建议记录的指标：打开会话到可交互耗时、恢复连接到收到新输出耗时、未确认提交数、草稿丢失/错误归属次数、切换会话操作步数、通知直达成功率、长时运行内存趋势。先测当前基线，再设性能目标；内容丢失、错误归属和重复执行应作为发布阻断条件。
