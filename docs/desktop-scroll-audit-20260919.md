# 电脑端整页滚动检查与修复（2026-09-19）

用户反馈：停在最新输出时，Cursor 终端似乎反复从上方滚回当前位置；预期是保持最新画面并更新。

## 已复现并修复

1. **到底部后，xterm 仍可能保留历史阅读状态。** TUI 清除滚动缓存后，视口距离为零，但 `isUserScrolling` 仍为 true。原来的 `scrollToLine(baseY)` 在距离为零时不执行；xterm 5.5 的 `scrollToBottom()` 同样经过零距离提前返回。现在使用至少一行的正向 `scrollLines`，由 xterm 将位置限制在底部，同时清除历史阅读状态，不修改私有状态。
2. **终端实际高度变化被遗漏。** 原来缓存外层面板尺寸，提示条或快捷栏变高时，面板尺寸不变，真实终端区域却变小。现在尺寸比较与 FitAddon 使用同一个终端父容器。修复前回归实测：终端仍为 22 行，而实际只能容纳 16 行。测试补齐真实桌面使用的 onResize 回调，避免无回调模式每次重新 fit 掩盖问题。
3. **其他区域的滚轮误改终端意图。** 提示条、快捷栏滚动以及 Shift 横向滚动会暂停终端跟随。现在仅处理 xterm 内部的纵向滚动，历史层仍使用自己的滚动逻辑。

后续还修复了一个会直接遮住 CLI 输入行的边界：远端快照可能把终端临时恢复为比可用区域更多的行，或字体指标变化但外层 Pane 尺寸不变。每次 fit 现在也会比较 FitAddon 的实际几何结果；行列不匹配就立即按终端可用区域重新 fit。新增回归确认最后一行在快捷命令栏上方。

目录树收起时，`#file-tree-resizer` 现在会被设置为 hidden 并从 flex 布局移除；正在进行的左侧拖拽也会取消。展开时仍保留原有调宽能力。

本轮直接修改了 `src/renderer/terminal-scroll-controller.ts`、`src/renderer/terminal-manager.ts`、`src/renderer/app.ts`、`src/renderer/styles.css` 和 `tests/e2e/desktop-scroll.e2e.mjs`；保留工作区原有的并行修改。

## 整页策略核对

| 区域/操作 | 当前行为与验证 |
| --- | --- |
| 页面、工作区、Pane 外层 | 固定布局、隐藏溢出；整页测试检查页面与终端外层 scrollTop 均为零 |
| 右侧会话列表、左侧文件树 | 各自独立滚动；真实鼠标滚动会话列表不改变终端意图或最新位置。目录树收起时，竖向调宽条不会显示、悬停或接收拖动 |
| 实时终端 | 跟随状态在输出解析后同步到底部；新增连续 25 次重绘的每帧位置与底部输入提示检查 |
| 用户上滚、拖选 | 暂停跟随，后续输出不抢历史位置；既有回归通过 |
| 回到底部、切换会话 | 恢复跟随；旧手势与延迟回调不覆盖新意图；既有回归通过 |
| 归档历史层 | 独立滚动、向下交回本地缓存，再回到最新；连续衔接套件 13/13 通过 |
| 提示条、快捷栏 | 滚动不改变终端意图；高度、快照或字体指标造成的行数不匹配都会按实际区域重新 fit，CLI 输入行保持在快捷栏上方 |
| 分屏、窗口尺寸变化 | 沿用 ResizeObserver 与定时兜底，尺寸缓存改为真实终端区域；未穷举实体桌面所有分屏组合 |
