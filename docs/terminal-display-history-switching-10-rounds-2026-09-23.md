# 终端显示、历史滚动与会话切换：十轮检查和优化

日期：2026-09-23。范围：Electron 桌面终端、手机 Web 终端、原生聊天视图。验证使用本地构建和模拟服务端的 Chromium 浏览器测试；未用真实手机或实际 CLI 长会话验收。

## 当前机制

- 主进程持续解析 PTY 输出，维护带序号的当前屏幕快照和可分页历史。桌面视图首次挂载、隐藏输出超预算或序号断档时取快照；历史层单独翻页，实时 xterm 只保留最近 120 行。
- 手机经 WebSocket 订阅会话，先接收 `replay`，再接收带序号的增量输出。旧输出通过历史层按需读取；新输出到达时，用户正在回看历史就保持原位置。
- 手机会话可选择终端或原生聊天。聊天通过 HTTP 轮询最新窗口，向上翻页加载更早消息。切换会话会重建终端视图，默认显示当前最新输出。

## 十轮结果

| 轮次 | 发现和处理 | 验证 |
| --- | --- | --- |
| 1 | 桌面新渲染器实例此前直接显示空 xterm，可能漏掉创建前的 PTY 输出；首次显示改为先取快照。 | 创建前已有输出的浏览器场景 |
| 2 | 手机切换会话期间旧聊天仍显示，且发送入口可能指向新会话；切换开始即停止轮询、关闭旧终端、隐藏旧视图并冻结输入。 | 延迟 `/api/sessions` 的浏览器场景 |
| 3 | 手机打开已有长聊天可能停在顶部；初次渲染后定位最新消息。 | 120 条聊天消息的首屏场景 |
| 4 | 加载更早聊天分页时，轮询到的新消息可能被旧缓存覆盖；响应合并时读取最新缓存。 | 分页请求期间追加消息的场景 |
| 5 | 桌面解析帧序号跳号时原先直接接受后续帧；现转入快照恢复，保留有界尾帧。 | 缺失序号的恢复场景 |
| 6 | 桌面重复选择当前会话时历史层可能留在屏幕上；重新选择时退出历史层，快照未完成时暂不跟尾。 | 历史恢复测试及桌面滚动测试 |
| 7 | 手机收到长 `replay` 就允许发送，而屏幕还在解析；现在首帧恢复完成后才开放输入。 | 延迟回放写入期间按钮禁用场景 |
| 8 | 桌面一次快照 IPC 拒绝后只能手动重选；瞬时失败在现有三次尝试额度内重试。 | 首次拒绝、第二次成功的场景 |
| 9 | 聊天轮询跨过本地缓存窗口时会拼成假的连续历史；仅在本地记录完整覆盖间隔时拼接。 | 大跨度分页窗口场景 |
| 10 | 轮询请求发出后完成的历史翻页可能被迟到轮询覆盖；轮询合并时以响应到达时的缓存为准。 | 翻页先完成、轮询后完成的场景 |

## 验证边界

`npm run build:ts`、`tests/e2e/mobile.e2e.mjs`、`tests/e2e/desktop-scroll.e2e.mjs` 和 `tests/e2e/terminal-history-recovery.e2e.mjs` 覆盖了本轮修改。浏览器测试使用模拟 IPC/HTTP/WebSocket；真机触摸惯性、实际网络抖动、实际 CLI 全屏程序及 Electron 冷启动尚需单独验收。
