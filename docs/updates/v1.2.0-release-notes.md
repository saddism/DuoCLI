## 中文

### 你好，又见面了 👋

这一版，我们重点解决了一个很真实的问题：**Cloudflare 隧道看起来在跑，但手机打开却是 502**。

原因很简单：隧道和后端服务是两套东西。隧道活着、本地 9800 挂了，公网就会报 Bad Gateway。以前你只能猜，现在 DuoCLI 会自己查、自己修、自己告诉你发生了什么。

---

### ✨ 亮点一览

#### 1. 三层健康检测 —— 不再被「假在线」骗到

DuoCLI 现在会定期检查：

| 层级 | 检测什么 | 意义 |
|------|----------|------|
| 本地 | `127.0.0.1:9800/ping.png` | 手机端依赖的后端是否真的在听 |
| 隧道 | cloudflared 进程 | Cloudflare 隧道是否由本机托管 |
| 公网 | `https://你的域名/ping.png` | 从外面能不能真正打开（502 也会被抓到） |

每 **20 秒** 自动巡检一次。不是只看进程，而是**真的去敲公网 URL**。

#### 2. 自动恢复 —— 502 了？让它自己爬起来

当检测到 **本地服务挂了** 或 **公网不可达** 时：

1. 自动重启本地远程服务（9800）
2. 清理僵尸 cloudflared（含旧版 `~/.config/duocli-tunnel` 路径）
3. 强制重启隧道，并轮询直到公网恢复

冷却 **60 秒**，避免疯狂重启。你也可以随时点 **「重试」** 手动触发。

#### 3. 右上角状态面板 —— 一眼看懂，不用猜

侧边栏「手机远程同步」区域现在会显示：

- 🟢 **healthy** — 公网 + 局域网均正常
- 🟡 **degraded** — 隧道或公网异常（会提示具体 URL）
- 🔴 **error** — 本地服务无响应
- 🟡 **retrying** — 正在自动恢复
- ⚪ **lan-only** — 仅局域网（未配置 cloudflared 时）

Token 默认打星号，点小眼睛 👁 临时查看，再点隐藏；显示时可点击复制。

#### 4. 多 Pane 工作区 —— 多个 AI 终端，一个桌面搞定

- 分屏、平铺、聚焦切换
- 布局持久化，重启后恢复
- 更适合同时跑 Claude / Codex / Kimi 等多会话场景

#### 5. 会话恢复 —— 关了还能接着聊

- 关闭终端时自动捕获各 CLI 的 resume 信息
- 侧边栏「已关闭会话」一键恢复
- 支持 Claude、Codex、Gemini、Kimi 等多家 CLI 家族

#### 6. Android 镜像与控制（预览）

- 桌面端可镜像 Android 设备屏幕
- 支持截图、点击、滑动、文字输入
- H264 / JPEG 双通道，弱网可降级

#### 7. 手机端体验升级

- 终端滚动与内容渲染更稳定
- 文件预览增强（图片 / 视频 / 音频 / PDF）
- 弱网提示与重连逻辑优化

## English

### Hey there 👋

This release tackles a frustrating real-world issue: **Cloudflare Tunnel looks fine, but your phone gets a 502 Bad Gateway.**

The tunnel and the local backend are separate processes. If cloudflared is up but nothing listens on port 9800, the public URL breaks. Previously you had to guess. Now DuoCLI **checks, fixes, and tells you what’s going on**.

---

### ✨ Highlights

#### 1. Three-layer health checks — no more “fake online”

DuoCLI periodically verifies:

| Layer | What it checks | Why it matters |
|-------|----------------|----------------|
| Local | `127.0.0.1:9800/ping.png` | Is the backend actually serving mobile clients? |
| Tunnel | cloudflared process | Is the Cloudflare tunnel managed on this machine? |
| Public | `https://your-domain/ping.png` | Can you really reach it from the internet? (502 counts as failure) |

Checks run every **20 seconds**. We don’t just look at processes — **we hit the public URL for real**.

#### 2. Auto-recovery — 502? Get back up automatically

When the local service is down or the public URL fails:

1. Restart the local remote server (port 9800)
2. Clean up stale cloudflared processes (including legacy `~/.config/duocli-tunnel` paths)
3. Force-restart the tunnel and poll until the public endpoint recovers

**60-second cooldown** between auto-retries. You can also tap **Retry** anytime.

#### 3. Status panel — see everything at a glance

The “Mobile Remote Sync” section in the sidebar now shows:

- 🟢 **healthy** — Public + LAN both OK
- 🟡 **degraded** — Tunnel or public URL issue (with the exact URL in the message)
- 🔴 **error** — Local service not responding
- 🟡 **retrying** — Auto-recovery in progress
- ⚪ **lan-only** — LAN only (when cloudflared isn’t configured)

Token is masked by default. Tap the eye icon 👁 to reveal temporarily; tap again to hide. Click the token to copy when visible.

#### 4. Multi-pane workspace — many terminals, one desktop

- Split, tile, and focus panes
- Layout persistence across restarts
- Built for running Claude, Codex, Kimi, and more side by side

#### 5. Session resume — pick up where you left off

- Captures resume metadata when you close a terminal
- “Closed sessions” in the sidebar for one-click restore
- Supports multiple CLI families (Claude, Codex, Gemini, Kimi, etc.)

#### 6. Android mirroring & control (preview)

- Mirror Android device screens on desktop
- Screenshot, tap, swipe, text input
- H264 / JPEG dual path with graceful degradation on weak networks

#### 7. Mobile client upgrades

- Smoother terminal scrolling and content rendering
- Richer file preview (images / video / audio / PDF)
- Better weak-network prompts and reconnect logic
- Spinner interception to reduce pointless reloads

---

### 🛠 Other improvements

- cloudflared scripts recognize legacy `~/.config/duocli-tunnel/config.yml`
- macOS one-click launcher scripts (`.command` / AppleScript)
- Configurable terminal auto-response (e.g. capacity prompts)
- Removed built-in Chat view and Windsurf proxy — focus on terminal + remote sync

### 🚀 After upgrading, do this

1. **Restart DuoCLI** (required for the new monitor to load)
2. Confirm the sidebar shows **healthy** (green dot)
3. Open the public URL on your phone once to verify

If you see “Public URL unreachable”, tap **Retry** or wait ~20s for auto-recovery.
