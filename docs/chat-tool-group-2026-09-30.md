# 对话界面过程消息合并为「执行任务」组

日期：2026-09-30。范围：手机 PWA 原生对话视图（`native-chat-view.js`）。

## 问题

一轮工作中 CLI 会产生大量非结论性的过程记录：Codex 每个 tool-call 是一条独立
assistant 消息、每份输出又是一条 `tool` 角色消息；Claude 的 assistant 消息带多个
tool-call 块，结果也是独立消息。逐条渲染成一堆「工具」胶囊，把真正的结论淹没。

## 改动

- **连续纯过程消息合并**：相邻的、只含 tool-call / tool-result 块的 assistant /
  tool 消息合并为一个折叠胶囊「执行任务 · N 个」；中间出现正文（text/图片等）
  即断组，正文仍逐条展示。
- **组内按 callId 配对**：调用与其输出合成一个条目（输入 + `—— 输出 ——` + 输出
  在同一个展开体里，复制按钮一并复制）；callId 未匹配的输出独立成项不丢内容。
- **汇总状态徽标**：有进行中的调用显示「进行中（N）」，有失败显示「N 个失败」，
  两者可并列（进行中不掩盖失败）；全部完成显示「已完成」。
- 单条过程消息不成组（不额外多一层折叠）；带正文的 assistant 消息（文字+工具）
  保持原样。
- 节点复用以组的首条消息为锚：轮询追加新过程消息不换锚、不重建整组，已展开的
  组保持展开；加载更早消息 prepend 不影响现有条目 key。
